# NEXORA — Real Pterodactyl Deployment Roadmap

## Current state

The GitHub Pages dashboard is a static frontend preview. It is not a Pterodactyl Panel installation and it cannot control a Minecraft server.

GitHub repositories and GitHub Pages do not provide a persistent Linux host, Docker daemon, Wings node, database, or permanent Minecraft server storage.

## Required infrastructure

Before installing the real Panel and migrating NEXORA, arrange a Linux server that provides:

- A supported Linux distribution (Ubuntu 24.04 LTS is the target for this project).
- Root or sudo access.
- Docker Engine support and permission to run it.
- Persistent disk storage for server files, backups, and databases.
- A public IP address and required network ports.
- A domain or subdomain for HTTPS.
- Enough RAM, CPU, and disk capacity for the Panel, Wings, and Minecraft workload.

A free-tier or trial host must be checked for its current limits, expiry, idle shutdown, bandwidth, storage persistence, and Docker restrictions. Do not assume that a provider's free tier is suitable for a 24/7 production server.

## Deployment order

1. Provision and secure the Linux host.
2. Install and configure the Pterodactyl Panel using the official documentation.
3. Configure the database, cache, web server, and HTTPS.
4. Create a Panel location and node.
5. Install Wings and connect it to the Panel using a node configuration generated by the Panel.
6. Verify that Wings reports healthy and that a test server can start and stop.
7. Configure a Minecraft Paper server and test Java connectivity.
8. Add Geyser and Floodgate only after the Java server is stable; configure Bedrock networking separately.
9. Back up the existing NEXORA server before any migration.
10. Transfer the world, plugins, configs, and other required files to the new server.
11. Verify plugin versions, permissions, worlds, player data, Java/Bedrock access, and backups.
12. Change DNS only after final testing and a rollback backup.

## Migration safety

- Keep the existing server untouched until the new server passes testing.
- Stop writes to the old server before taking the final world and player-data backup.
- Never upload server secrets, database passwords, Panel application keys, node tokens, or private keys to GitHub.
- Store secrets in the host's protected environment/configuration files, not in this repository.
- Do not run an unreviewed remote script as root.
- Test restore procedures before relying on backups.

## Repository versus live services

| Component | Can live in this GitHub repository? |
|---|---|
| Dashboard HTML/CSS/JavaScript | Yes |
| Documentation and reviewed install scripts | Yes |
| Panel PHP application runtime | No |
| Database service | No |
| Wings daemon | No |
| Docker daemon and containers | No |
| Persistent Minecraft world storage | No |
| 24/7 Minecraft server process | No |
